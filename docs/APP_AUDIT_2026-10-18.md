# Content Studio Audit: 2026-10-18

Version: **1.6.1**. Scope: the current checkout, including the previously uncommitted article, Pinterest, Meta, Quality Studio, Content Pipeline, reader plugin, analytics, and optional worker upgrades.

## Findings Fixed

1. **High: nested workspace updates could destroy array structure.** Updating or deleting `articles.0.*` converted the article array into an object. Nested updates now preserve arrays and untouched records, create missing array containers correctly, reject prototype-related paths, and read only own properties.
2. **High: restore observers could see partial or rolled-back data.** Database replacement emitted notifications for every row inside the transaction. Notifications now occur once after commit, never for a rollback. A settings write failure rolls back the workspace transaction and restores previous settings; facade observers see only the complete successful restore.
3. **High: CSV retry eligibility could become stale in the save dialog.** Import results could change to confirmed after the initial failed-only check. Eligibility and outstanding exports are checked again after the dialog and immediately before staged files are committed. Changed image bytes or URLs also stop the final commit.
4. **High: download progress could overwrite newly saved receipt outcomes.** Progress updates now preserve the current revision, receipt events, and outcomes instead of writing an older manifest snapshot over them.
5. **Medium: complete-looking recipe collections could hide duplicate primary IDs.** Quality inspection now rejects repeated `recipe-card` IDs while still inspecting every uniquely identified recipe. Shopping-list attribution retains all contributing recipe names.
6. **Medium: invalid recipe-pack multipliers were silently replaced.** Zero and blank multipliers no longer become one. Zero, blank, negative, nonfinite, and out-of-range inputs fail validation.
7. **Medium: duplicate analytics rows could inflate scheduling evidence.** Repeated records for the same Pin cannot count as independent samples. Sparse evidence continues to use a fallback window, not a best-time claim.
8. **Medium: misleading usability counts and legacy draft crashes.** Visually reviewed Pins require a real image fingerprint before they count as usable. Untitled saved drafts receive a safe display title.
9. **Medium: receipt drafts could be lost after a save failure.** Pending drafts remain queued until the write succeeds; newer edits are not removed by older completions. Receipt import disables batch changes while the native file import is in progress.
10. **Defense in depth: article preview active content.** Preview sanitization now removes SVG and MathML containers as well as scripts, event handlers, and other active elements. Ordinary recipe text and raster image links remain intact.
11. **Compatible dependency patches.** Updated `qs` to the patched 6.16.1 line and `postcss-selector-parser` to 7.1.6. Added a pinned Playwright development dependency and a compiled UI test runner so tests no longer depend on this computer's private bundled browser package or repeated development-server optimization.

The CSV default remains **90 minutes / 1.5 hours**, remains editable, and does not overwrite deliberate row dates.

## Remaining Limitations

- The full development dependency graph still reports **13 advisories: 5 high and 8 moderate**, down from 18 before the compatible parser updates. They are build-time chains involving Tailwind 3 (`braces`/glob/watch dependencies) and Electron packaging (`sprintf-js`/proxy logging dependencies), not production app or worker runtime dependencies. The registry's current `braces` 3.0.3 and `sprintf-js` 1.1.3 releases remain affected. A major framework migration or packaging downgrade was not forced into this audit. Build only trusted source/configuration and track upstream fixes.
- The Windows Playground runtime can print stale-temp-directory or file-unlock warnings. Its exit status and independently verified PHP assertion receipt, rather than warning text, determine staging success.
- Live Pinterest CSV import acceptance, real OAuth accounts, paid Replicate generation, real external hosting reliability, and live WordPress publishing were not tested. No paid prediction, live post, or server deployment was performed.
- Human recipe, image realism, spelling, and platform-import review remain necessary. Structural validation does not establish kitchen testing, nutritional accuracy, or universal food safety.
- Local desktop tests ran on Windows. Linux/macOS behavior is covered by the configured GitHub jobs, not by an asserted local run.
- No installer, signing certificate, local workspace database, cache, or temporary test data belongs in the GitHub source push. The earlier 1.6.0 unsigned installer is unchanged; this audit updates the 1.6.1 source, not that installed binary.

## Security References

The application controls were checked against the [official Electron security checklist](https://www.electronjs.org/docs/latest/tutorial/security), including context isolation, sandboxing, trusted-frame IPC validation, navigation restrictions, permission denial, CSP, custom protocols, and package fuses. These controls reduce risk; they are not proof that no vulnerability exists.
